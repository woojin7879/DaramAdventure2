# 다람이의 모험 2 기획 및 개발 계획

작성일: 2026-09-10 · 수정일: 2026-09-11 · 상태: 1년차 플레이 초안 v0.2

## 1. 목표와 전제

기존 Unity 게임의 다람이를 주인공으로, 설치 없이 웹 브라우저에서 즐기는 JavaScript 기반 뱀파이어 서바이버류 생존 액션 게임을 만든다. 원작의 다람이, 도토리, 사계절, 속성 스킬, 겨울 곰 보스를 새로운 전투 구조로 연결한다.

사용자가 확정한 방향은 **다람이 외형 정체성 유지 / 게임에 맞춘 에셋 신규 제작 / 브라우저 / JavaScript / 생존 액션 / 계획서부터 시작**이다. 추가 확정 방향은 **계절당 5분 / 사계절 후 최종 보스 / 연차별 맵 / 일반 경험치는 점 / 특별 보상만 도토리 / 원작 속성 무기 조합 / 이야기는 연차 클리어 때만 / 매년 전투 성장 초기화 / 무기 최대 6칸**이다. 보스 제한 시간, 이야기 세부 설정은 아래 제안으로 구분한다.

## 2. 게임 콘셉트

> 첫 겨울잠에서 깨어난 다람이가, 이상해진 숲에서 사계절을 버티며 부모님이 남긴 흔적을 따라 해마다 더 깊은 곳으로 향한다.

- 제목: 다람이의 모험 2 / Darami Adventure 2. 프로젝트 폴더는 daramsurvivors를 유지한다.
- 화면: 위에서 내려다보는 2D 필드에 원작의 정체성을 유지하며 새로 제작한 다람이를 배치한다.
- 조작: 이동 중심, 공격은 자동. 피할 경로와 성장 조합을 선택하는 재미에 집중한다.
- 한 판: 연차 하나. 봄·여름·가을·겨울 각 5분, 총 20분 생존 후 해당 연차의 최종 보스.
- 최종전 제안: 3~5분을 목표로 조정하되 강제 시간 초과 패배는 두지 않는다. 체력 0이면 패배한다.
- 연차 진행 제안: 보스 처치 → 연차 엔딩 → 다음 연차 맵 해금. 연차를 선택해 한 판씩 플레이한다.
- 스토리와 맵 초안: [STORY_AND_MAPS.md](STORY_AND_MAPS.md). 후속작 1년차는 원작의 첫 겨울잠 다음 해다.
- 핵심 정체성: 도토리 수집, 따뜻한 숲의 색감, 다람이의 큰 꼬리와 몸짓, 사계절의 변화.

## 3. 플레이 흐름과 조작

타이틀 → 연차 선택 → 봄·여름·가을·겨울 전투와 성장 → 연차 최종 보스 → 클리어 저장·다음 연차 해금 → 연차 엔딩 이야기 → 결과.

이야기는 연차 클리어 후에만 재생한다. 시작·계절 사이·보스 직전에는 대사나 컷신 없이 진행하고, 계절 전환은 짧은 계절명 표시와 환경 변화로 전달한다. 패배 시에는 결과와 재도전만 제공한다.

| 입력 | 동작 |
| --- | --- |
| WASD / 방향키 | 8방향 이동, 대각선 속도 정규화 |
| Esc | 일시정지 / 재개 |
| 마우스 클릭 / 숫자 1·2·3 | 레벨업 선택 |

레벨업 중에는 전투와 게임 시간이 정지한다. 브라우저 탭이 비활성화되어도 자동으로 정지하고, 복귀 후 명시적으로 재개한다. 이동키의 페이지 스크롤을 막고 포커스를 잃으면 눌린 키 상태를 초기화한다.

## 4. 첫 완성 버전의 범위

### 캐릭터와 필드

- 플레이어 1명: 원작 다람이. 좌우 반전과 대기·걷기·피격 애니메이션 적용.
- 연차마다 고유 맵을 둔다. 먼저 1년차 귀환의 숲을 완성하고 같은 진행 구조로 후속 맵을 추가한다.
- 각 연차 맵 안에서 사계절이 바뀌며 팔레트·환경 현상·적 구성이 변한다. 맵별 지형과 전투 차이는 별도 스토리·맵 문서에 정의한다.
- 플레이어와 적의 충돌은 단순 원형 판정. 첫 버전은 이동을 막는 복잡한 지형을 넣지 않는다.
- 피격 후 짧은 무적 시간과 깜빡임을 제공하고, 접촉 피해가 매 프레임 중복되지 않게 한다.

### 무기와 성장

**원작 속성 계승 8종 + 부적·포자·벌떼·비축고, 총 12종을 채택했다:** W01 도토리 새총, W05 꼬리 휩쓸기, W06 조약돌 궤도, W08 덩굴 채찍, W13 불씨 도토리, W14 가지 번개, W15 눈송이 고리, W17 도토리 당구, W19 나무껍질 부적, W09 버섯 포자, W11 벌떼 친구, W18 겨울 비축고. 동시 장착은 시작 무기를 포함해 **최대 6칸**이다. 무기별 최대 레벨과 단계별 효과는 [WEAPON_PROGRESSION.md](WEAPON_PROGRESSION.md)를 기준으로 한다. 새총·조약돌·불씨·번개·벌떼·비축고는 8레벨, 덩굴·당구·부적·포자는 7레벨, 꼬리·눈송이는 6레벨이다. 최대 레벨과 수치는 구현 초안이며 플레이테스트로 조정한다. 진화는 같은 슬롯을 교체하는 후속 제안으로 구분한다.

매년 시작할 때 레벨·무기 강화·진화·패시브 등 전투 성장을 초기화한다. 같은 해의 계절 간에는 유지하고, 지도 해금과 이야기 기록은 보존한다.

프로토타입은 기본 도토리 탄환 1종으로 전투를 먼저 검증한다. 이후 선택된 무기를 추가한다. 공격력·공격 주기뿐 아니라 궤도, 관통, 반사, 설치, 이동 연계로 플레이 차이를 만든다. 패시브는 공격력, 공격 주기, 범위, 최대 체력, 이동 속도, 획득 반경의 6종을 초안에 적용한다.

레벨업 후보는 새 무기와 보유 능력 강화에서 중복 없이 3개를 뽑는다. 6칸이 차면 새 무기 후보를 제외한다. 최대 레벨 항목은 제외하고 후보가 부족하면 가능한 항목만 표시한다. 모든 항목을 완성한 뒤에는 체력 회복을 제공한다. 경험치를 한 번에 많이 얻으면 레벨업 선택을 순서대로 처리한다.

일반 적은 **작은 점 형태의 경험치**를 드롭한다. 가까이 가면 흡수하고 레벨업에 사용한다. 점의 크기와 밝기로 경험치 양을 구분한다. **필드 보상 중 도토리 형태는 특별 아이템에만 사용한다.** 공격용 도토리는 계속 사용하되 궤적·크기·테두리로 보상과 구분하고 경험치나 특별 아이템을 소비하지 않는다.

특별 도토리는 자석·계절 버프·고경험치 후보를 중심으로 검토한다. 세부 효과는 아직 미확정이며 기존 볼주머니·숙성 시스템은 보류한다. 이야기의 단서는 전투 드롭 확률과 분리해 연차 최종 보스 처치 후 엔딩에서 확정 제공한다.

### 적과 계절

| 전투 누적 시간 | 계절 | 기본 구성 |
| --- | --- | --- |
| 0:00–5:00 | 봄 | 해당 연차의 적과 지형을 학습 |
| 5:00–10:00 | 여름 | 빠른 적과 환경 압박 추가 |
| 10:00–15:00 | 가을 | 튼튼한 적과 밀집 전투 |
| 15:00–20:00 | 겨울 | 혼합 웨이브와 최종전 예고 |
| 20:00 이후 | 최종전 | 연차별 고유 보스, 처치 시 클리어 |

시간은 전투 시간이며 이야기·레벨업·일시정지는 포함하지 않는다. 계절마다 새 5분 구간을 시작한다. 마지막 30초에는 정예 웨이브를 넣는 안을 제안하되, 처치 여부가 계절 종료를 지연하지 않는다.

일반 적은 느린 추적형·빠른 추적형·튼튼한 추적형의 3종이다. 외형은 원작을 참고하되 전투 역할에 맞춰 새로 제작하고, 제작 전에는 임시 그래픽으로 구분한다. 적은 화면 밖이면서 맵 내부인 위치에 생성한다.

1년차 보스는 원작 곰을 떠올리게 하는 꿈의 잔영으로 제안한다. 원작 곰이 부활했다고 확정하지 않는다. 공격은 예고 후 돌진과 주변 범위 공격으로 시작한다. 후속 연차에는 고유 보스를 둔다. 공격 범위와 준비 시간을 시각적으로 알린다. 원작의 겨울 미끄러짐과 가을 함정은 첫 버전에서는 제외하고, 조작감이 완성된 뒤 별도 도전 요소로 검토한다.

### UI와 저장

- 전투 HUD: 체력, 경험치, 레벨, 연차, 계절 남은 시간, 계절, 처치 수, 보유 무기.
- 레벨업: 능력 이름, 현재/다음 레벨, 실제 효과 변화가 보이는 선택 카드.
- 결과: 승패, 생존 시간, 처치 수, 최종 레벨, 무기 조합, 재시작 버튼.
- 설정: 음량, 효과음, 화면 흔들림 켜기/끄기.
- 로컬 저장: 최고 기록, 설정, 해금 연차, 감상한 이야기, 계절 경계 이어하기 데이터. 저장 데이터에 버전을 두고 손상되면 기본값으로 복구한다.
- 첫 클릭 이후 소리를 활성화하고 저장 불가 환경에서도 플레이는 가능하게 한다.

## 5. 기술 설계 제안

첫 구현은 **JavaScript ES Modules + Canvas 2D + HTML/CSS UI**로 구성한다. 첫 초안은 외부 패키지 없이 Node.js 기본 서버와 복사 기반 정적 빌드로 실행한다. Unity WebGL 변환 대신 플레이 로직을 JavaScript로 새로 구현하고 게임에 맞춘 신규 에셋을 적용한다.

전투는 Canvas에, 메뉴와 선택 카드는 DOM에 렌더링한다. 서버, 로그인, DB 없이 정적 파일로 실행하는 구조를 목표로 한다. 첫 대상은 데스크톱 키보드 브라우저이며 Chrome·Safari·Firefox에서 확인한다. 모바일 터치 조작은 후속 단계다.

```text
daramsurvivors/
  README.md
  docs/
    PLAN.md
    UNITY_REFERENCE.md
    DESIGN_OPTIONS.md
    STORY_AND_MAPS.md
    WEAPON_PROGRESSION.md
  index.html                 # 아래 파일과 폴더는 구현 단계에서 생성
  package.json
  public/assets/
    characters/daram/
    enemies/
    environments/
    effects/
    audio/
  src/
    main.js
    game/                    # 루프, 상태 전환, 입력, 카메라
    entities/                # 플레이어, 적, 투사체, 경험치
    systems/                 # 생성, 공격, 충돌, 성장, 저장
    data/                    # 무기, 강화, 계절별 웨이브 수치
    rendering/               # 스프라이트, 파티클
    ui/                      # HUD, 메뉴, 레벨업, 결과
    styles.css
```

게임 상태는 TITLE / YEAR_SELECT / YEAR_END_STORY / PLAYING / LEVEL_UP / PAUSED / BOSS / RESULT로 분리한다. 시뮬레이션은 고정 시간 간격으로 갱신하고 렌더링은 requestAnimationFrame으로 진행한다. 긴 프레임 뒤에는 누적 갱신 횟수를 제한해 복귀 순간의 급격한 진행을 막는다.

데이터와 전투 로직을 분리해 소스 여러 곳을 수정하지 않고 수치를 조정한다. 재시작할 때 적, 투사체, 입력, 타이머, 이벤트 상태를 모두 초기화한다.

## 6. 아트 제작 방향

**원작 에셋은 레퍼런스로 삼고 실제 게임용 에셋은 새로 제작한다. 다람이의 생김새 정체성은 유지한다.** 갈색 몸통, 밝은 얼굴과 배, 큰 말린 꼬리, 작은 귀와 짧은 팔다리의 비율을 기준으로 원작과 비교한다. 새로운 의상이나 장비가 얼굴과 꼬리를 가리지 않게 한다.

신규 픽셀 아트를 기본 제안으로 두되 구체적인 화풍과 프레임 규격은 캐릭터 시안에서 결정한다. 먼저 원작과 나란히 비교할 대기 자세 시안을 만들고, 다람이로 읽히는 디자인을 고른 뒤 이동·피격 애니메이션으로 확장한다. 시안과 실제 투명 배경 스프라이트 제작을 구분하고, 프레임별 비율·색·발 기준점을 통일한다.

배경, 적, 무기, 경험치도 같은 화풍으로 제작한다. 작은 실제 플레이 크기에서 다람이의 얼굴·꼬리가 읽히고, 적과 경험치가 분리되어 보여야 한다. 원작 플랫폼용 타일을 그대로 적용하지 않고 평면 이동에 맞는 필드를 만든다.

원작 조사 기록은 [UNITY_REFERENCE.md](UNITY_REFERENCE.md), 신규 제작 기준은 [DESIGN_OPTIONS.md](DESIGN_OPTIONS.md)에 둔다. 신규 이미지들을 생성해 첫 플레이 초안에 적용했다. 제작 기록은 [ASSETS.md](ASSETS.md)를 따른다.

## 7. 개발 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0. 기획 | 원작 조사, 방향과 범위 정리 | 계획서와 원작 참조 문서 존재 |
| 1. 이동 프로토타입 | 개발 환경, 다람이 에셋, 입력, 카메라 | 다람이 이동·대기·좌우 반전, 리사이즈와 포커스 복구 정상 |
| 2. 전투 루프 | 적 1종, 기본 탄환, 피해, 경험치 점, 레벨업 | 3분간 성장하며 플레이하고 사망·재시작 가능 |

## 8. 검증과 성능 목표

- 일반 플레이에서 60fps를 목표로 하되, 실제 테스트 기기·브라우저·해상도를 함께 기록한다.
- 부하 기준 초안: 적 300개, 투사체 200개, 경험치 점 500개 동시 존재. 먼저 측정하고 병목에 맞춰 공간 분할, 객체 재사용, 경험치 병합을 적용한다.
- 기능 검증: 대각선 속도, 자동 공격 주기, 무적 시간, 경험치 누적, 강화 상한, 보스 승패, 일시정지 중 타이머 정지.
- 반복 검증: 시작과 재시작을 반복해 이벤트 중복과 개체 잔존 여부를 확인한다.
- 화면 검증: 작은 창과 고해상도 화면에서 HUD와 선택 카드가 잘리지 않아야 한다.
- 브라우저 검증: Chrome·Safari·Firefox에서 입력, 오디오, 저장, 탭 복귀, 결과 화면을 확인한다.
- 자동 테스트는 성장 계산·피해 판정·상태 전환처럼 규칙이 있는 로직에 집중하고, 조작감과 가독성은 직접 플레이로 평가한다.

## 9. 이후 확장

모바일 조작 다듬기, 무기 진화, 영구 성장, 캐릭터 스킨, 추가 연차 맵과 보스 순으로 검토한다. 멀티플레이, 계정, 온라인 랭킹, 결제는 첫 완성 버전에 포함하지 않는다.
